# Aegis P1 Ideate

## Overview

把"想要什么"变成"用户签字确认过的需求"。
**本阶段禁止写任何业务代码，禁止进入设计。**

核心原则：**没签字的需求 = 没需求。**

## When to Use

- 用户说"做个 X""加个功能"，但还没讨论清楚
- PRD 存在但未获用户确认
- 需求含糊、有歧义、或用户自己也没想清

## 动作

### 1. 分轮提问（不要一次问完）

**第一轮 · 目标与边界**
- 解决谁的什么问题？
- 什么算成功（可测）？
- **明确不做什么？**（非目标）

**第二轮 · 用户与场景**
- 谁用、什么情况下用？
- 主流程一步步是什么？

**第三轮 · 约束**
- 技术限制、时间限制、与现有系统关系？

**第四轮 · 界面（前端项目必问）**
- 有哪几个关键界面？
- 每个界面的核心元素？
- 交互风格偏好？

> 一次问 3-5 个。用户答得含糊就追问到具体。

### 2. 写 PRD

按 `.ai/99-reference/prd-schema.md` 六节，写入 `docs/prd.md`。

### 3. 逐条核对（关键，不可省）

不要只说"PRD 已生成"。必须逐条念：

```
PRD 已写入 docs/prd.md，请逐条确认：

1. 目标：<...>
2. 非目标：<...>
3. 关键界面：<...>（决定 P2 出几个 demo）
4. 验收标准：
   - <可测标准>

是否正确？需要调整请指出。
```

### 4. 等待明确肯定词

判定标准：用户说出「确认」「可以」「没问题」「就这样」等**明确肯定**。
模糊回应（"嗯""看起来行""差不多"）**不算确认**，需再次询问。

## 完成标准

- [ ] PRD 六节齐全，非目标非空且具体
- [ ] 验收标准每条可测
- [ ] 前端项目：关键界面清单非空
- [ ] `bash scripts/gate.sh P1` 输出 PASS
- [ ] 用户给出明确肯定词
- [ ] 签字已写入 `STATE.md`

## Common Mistakes

| 错误 | 纠正 |
|---|---|
| 跳过提问直接写 PRD | 需求跑偏，后期全返工 |
| 非目标写"暂不考虑其他" | 等于没写，必须写具体不做什么 |
| 验收标准写"体验良好" | 不可测，改成可观察的指标 |
| 生成 PRD 后不逐条核对 | 用户没真读，问题延后暴露 |
| 把"嗯"当确认 | 必须等明确肯定词 |

## Red Flags — STOP

- "需求已经很清楚了，不用问" → 清楚的是你，不是用户
- "先写代码，PRD 后面补" → 违反铁律一
- "用户没回，应该默认同意" → 绝不允许

## 与通用框架的关系

Superpowers 的 `brainstorming` 可用于提问框架，
但**产出必须落 `docs/prd.md` 六节结构**，且**不能替代逐条核对与签字**。
