# Aegis State

## Overview

本项目的开机自检。任何会话、任何 agent，在动手前必须先确定**自己在哪个阶段**，
否则会跳步、自作主张、丢失上下文。这正是跨会话不一致的根因。

**核心原则：阶段锁定 > 通用方法论 > agent 默认行为。**

## When to Use

- 任何新会话开始
- 不确定当前项目的阶段、进度、下一步
- 用户要求做某事，但不确定是否被允许（阶段是否够）

## 动作

### 1. 按序读取（只读这 4 个，不要读全项目）

```
① AGENTS.md
② STATE.md
③ .ai/00-core.md
④ .ai/90-preferences.md
```

然后按 `STATE.md` 的当前阶段，加读 `.ai/0X-Pn-*.md`。

### 2. 声明当前坐标

```
当前阶段：P2 设计
当前迭代：v1.2 用户登录
本次目标：<用户要什么>
已加载：00-core, 90-preferences, 03-P2-design
```

### 3. 判断请求是否越界

对照「阶段-动作权限表」检查用户请求是否被当前阶段允许：

| 用户请求 | 允许的阶段 | 若不在该阶段 |
|---|---|---|
| 讨论需求、写 PRD | P1 | 提示先回 P1 |
| 设计架构、出 demo | P2 | 提示先完成 P1 确认 |
| 写业务代码 | P4 | **拒绝**，提示当前缺什么 |
| 交付 | P7 | 提示先过 P5/P6 |

## 越界处理（硬规则）

当用户请求超出当前阶段权限时：

1. **不要直接做**，也**不要直接拒绝**
2. 说明：当前在 Pn，进入 Pm 需要先完成 <缺失的制品/门禁>
3. 给出两条路：
   - 「我现在补做 X，然后继续」
   - 「您明确要求跳过 X，我记录豁免后直接做」
4. 等待用户选择

**禁止行为：**
- 自行判定"用户应该同意了"而跳步
- 在 `STATE.md` 伪造签字
- 因为"很简单"而豁免门禁

## Red Flags — STOP 并重新走流程

| 想法 | 现实 |
|---|---|
| "这个改动很小，不用走流程" | 小改动造成的返工最多 |
| "用户看起来着急，先做了再说" | 跳步的代价由用户承担 |
| "PRD 大概清楚了" | 没签字就是不清楚 |
| "demo 可以后面补" | 先代码后 demo = 返工 |
| "我记住规矩了，不用读文件" | 规矩会变，必须读当前版本 |

以上任一出现 → 回到步骤 1。

## 完成标准

- [ ] 已读 4 个必读文件
- [ ] 已声明当前阶段与本次目标
- [ ] 已确认请求在阶段权限内，或已获得豁免
