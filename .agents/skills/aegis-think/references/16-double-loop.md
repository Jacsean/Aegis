# 双环反思（回头看看目标本身）

## 它逼你想什么

单环问"做法对不对"，双环问"**目标本身对不对**"。大多数时候单环就够，只有单环修不好时才该质疑目标。

**误用它比不用它更糟**：有实测——只做检测不做修复，整体效果是负的（ΔC = −0.236，每个 run 都为负）。

## 什么时候触发（只认外部信号）

| 触发 | 说明 |
|---|---|
| **用户说**"不对 / 不是这样 / 偏了" | 最强信号 |
| **客观检查连续失败 ≥2 次** | 测试红、跑不通、报错 |
| **与事先写下的可执行规格不符** | 规格是二值的，不是主观感觉 |

**不触发**：你自己觉得"好像有点偏" → **不触发**。宁可漏报，不要误报。

> 依据：有研究给出信息论结论——任何只观察生成文本的门，都无法在文本不可区分的环境里可靠改进；必须绑定环境验证的信号。所以"我觉得可疑"不是可用触发源。

## 怎么执行（一轮，不许两轮）

### 第一步 · 先摆对照（三行，不许长）

```
我理解的预期：<引用用户的原话，不许复述>
实际产出：<客观描述：做了什么、跑没跑通>
差异：<有就列，没有就写"我没看出差异">
```

**为什么必须引原话**：不引的话，你会用自己的宽松理解代替预期——那样永远不会发现偏。
**为什么要你先列差异**：让用户自己回忆 + 对照，等于把活丢回给他。

### 第二步 · 问一句

「算不算偏？」

### 第三步 · 用户说偏了，做三问

```
1. 当初定的目标，原话是什么？
2. 现在在做的，和它哪里不一致？（具体到一处，不许说"有点偏"）
3. 三选一，必须选一个：
   A. 目标不变，改做法（回单环）
   B. 目标要改，说明为什么、改成什么
   C. 目标没错，是任务太大，拆
```

**不许只"意识到偏离"就结束**——检测必须配动作，否则效果是负的。

## 什么时候问（里程碑级，不是每步）

| 算里程碑 | 不算 |
|---|---|
| 一个任务 / 功能做完 | 写完一个文件 |
| 一个阶段结束 | 跑完一次测试 |
| 用户主动问"做完了吗" | 中间过程汇报 |

## 和 aegis-think 的分工

| 时点 | 谁 | 问什么 |
|---|---|---|
| 有新目标时 | `aegis-think` | "我判断你要的是 X，对吗？" |
| 有新结果时 | 本模型 | "我理解的预期是 A，做出的是 B，算不算偏？" |

一个管入口（要什么），一个管出口（做对没）。不重复。

## 能力边界（必须说清，不许隐瞒）

**它救不了你的情况**：真的偏了、但你也没发现、客观检查也没报错 → **不会触发**。

这是刻意取舍：**宁可漏报，不要误报**。因为乱提示会让用户不再信任提示，而信任一旦丢了，整套机制就废了。

## 什么时候不该用

- 目标明确、结果符合、用户也没说话 → 不反思
- 同一个问题已经双环过一次 → **不重复双环**（实测：第一轮之后价值归零，第四轮破坏性与修正相当）
