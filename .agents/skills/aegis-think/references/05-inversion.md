# 逆向思维

## 它逼你想什么

不问"怎么做好"，反问"**怎么做才能彻底搞砸**"。因为失败的原因往往比成功的原因更清楚、更具体。

## 怎么用

1. 把目标反过来：**"要让用户彻底不满意，我该怎么做？"**
2. 列出 5-8 条"搞砸的方法"
3. 回头检查：我现在的计划，有没有不小心踩中其中几条？
4. 踩中的那条，就是该问用户的地方

## 例子

> 目标：做个贪吃蛇。

**"要让它彻底没法用，我该怎么做？"**
- 做成命令行版 → 用户双击打不开
- 做成需要装环境的 → 用户机器没装
- 手机打开发现不能触屏
- 玩完一局必须刷新页面才能再玩
- 死了不告诉用户为什么死

→ 回头看计划：如果我只打算给一个 `.py` 文件，第 1、2 条就踩中了。

→ 这就该问："你要源码自己跑，还是要直接能玩的？"

## 什么时候不该用

- 已经很清楚用户要什么、且没有失败史
- 纯创意发散阶段（这时候反过来会压制想法）
