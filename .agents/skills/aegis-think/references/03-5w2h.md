# 5W2H

## 它逼你想什么

一个任务有七个面，人通常只看到两三个。**没看到的那些，就是后来返工的原因。**

| 项 | 问什么 | 常见漏项 |
|---|---|---|
| **W**hat | 具体是什么东西 | 形态：网页？脚本？文档？ |
| **W**hy | 为什么需要它 | 真实动机（往往和说的不同） |
| **W**ho | 谁用、谁维护 | 只有他？还有别人？ |
| **W**hen | 什么时候要 | 现在就要，还是下周？ |
| **W**here | 在哪运行、在哪看 | 电脑？手机？他的机器？ |
| **H**ow | 怎么算做完、怎么用起来 | 交付形态：文件？部署好？ |
| **H**ow much | 多少算够 | 功能几个？花多久？多少钱？ |

## 怎么用

七项快速扫一遍，**问自己哪几项是空的**。空的那项就该问用户。

不必七项都问——**只问"空着会导致做错"的那两三项**。

## 例子

> 用户说："做个贪吃蛇。"

| 项 | 状态 |
|---|---|
| What | ❌ 网页？终端？脚本？ |
| Why | ❌ 自己玩？给别人看？教学演示？ |
| Who | ❌ 只有他？ |
| When | ❌ 现在？ |
| Where | 🟡 他说了"浏览器" |
| How | ❌ 要能直接玩，还是要源码？ |
| How much | ❌ 几条命？难度？分数？ |

→ 至少该问 What、Why、Where 里的两条。

## 什么时候不该用

- 用户已经把七项都说了（这时再问就是浪费对方时间）
