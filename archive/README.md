# archive — 归档区

> 这里放**不再参与开发、但值得留着**的文件。
>
> 由 P6 归档阶段使用，规则见 `.ai/07-P6-archive.md`。

---

## 什么该放这

| 目录 | 放什么 | 判断标准 |
|---|---|---|
| `scripts/` | 一次性脚本（数据迁移、批量修复、临时爬虫） | 已经跑完了，以后可能还要查"当时是怎么处理的" |
| `fixtures/` | 大体积测试数据（>1MB） | 留在 `tests/` 会拖慢 clone |
| `releases/` | 超过 2 个版本的旧交付说明 | `docs/release/` 只留最近 2 个版本 |

## 什么不该放这

- **源码**（`src/`）—— 它在版本控制里，不需要归档
- **测试**（`tests/`）—— 同上
- **正式文档**（`docs/` 下）—— 它们是资产，不是垃圾
- **HTML demo**（`docs/design/demo/`）—— 这是用户确认过的设计证据，永久保留

---

## 归档不等于删除

`archive/` 里的东西**仍然在 git 里**。归档的含义是"不再被主动引用"，不是"丢弃"。

真要删除 → `git rm` 并在 CHANGELOG 的「移除」一节写清原因。

---

## 清理规则

`archive/` 每积满一年审视一次：

- 连续一年没被任何文档引用的 → 可以真删
- 仍被引用的 → 移回正式位置

> 归档区的价值是"可追溯"，不是"留着一堆不知道是什么的文件"。
