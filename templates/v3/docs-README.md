## 目录约定（该放哪）

按**用途**分，不按创建时间分。

| 目录 | 放什么 | 什么时候建 |
|---|---|---|
| `reference/` | 术语表、配置项说明、API 参考 —— **只陈述事实，不带解释** | 装好就有了 |
| `guides/` | 怎么装、怎么配、怎么用 —— **有基础的人解决具体问题** | 第一次写使用说明时 |
| `explanation/` | 为什么这样设计、架构背景 —— **回答"为什么"** | 有设计需要解释时 |
| `tutorials/` | 零基础走一遍 —— **作者掌控全局，读者跟着做** | 需要教学时 |
| `adr/` | 架构决策记录 —— **一份决策一个文件**，写"选了什么、为什么、否决了什么" | 做出第一个重要技术选择时 |
| `incidents/` | 故障记录 —— **「预防」一栏必填** | 第一次出事时 |
| `release/` | 每个版本的发布说明 | 第一次发版时 |
| `rfc/` | 提案与讨论 —— 动手前把方案摆出来 | 需要多人对齐方案时 |

**不要自造目录名**。上面没有的用途，先想想能不能归到已有目录里。

## 模板在哪

需要新建某类文档时，先看有没有现成模板：

```
.aegis/templates/          ← 安装时放进来，需要时 copy 到 docs/ 对应目录
├── adr/ADR-0001-template.md
├── incidents/INC-0001-template.md
└── release/RELEASE-template.md
```

**用法**：`cp .aegis/templates/adr/ADR-0001-template.md docs/adr/ADR-0001-<你的标题>.md`
