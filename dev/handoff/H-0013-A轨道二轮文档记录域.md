# H-0013 A 轨道二轮：③域四词定案，删掉「节点」

- **时间**：2026-10-21
- **谁**：agent 执行，用户「下一步」授权
- **事件**：查 ③ 文档记录域剩余四词（记录 / 索引 / 事件 / 来龙去脉），四词均给出定义（`暂定`）；另删掉 agent 自造的「节点」
- **为什么这样处理**：③域是 handoff 机制的词根，不查清它，「地点」「分支」虽然定了也落不到 schema 上
- **怎么处理的**：取证（贴原文出处）→ 用用户原话试填 → 判定 → 给定义；用户从未用过的词按判据剔除
- **试过什么**
  - ❌ 保留「节点」：全仓只出现 3 次，全是 agent 写的（H-0009 的「三节点链」、五域计划、待查清单），用户从未使用；它要表达的就是「记录」——属于为填格子造词
  - ❌ 把「记录」定义成「索引里的一行」：那是用户当初的原话（「搜索…定位文档内容的位置行」），但按两层结构，行是索引、记录是文件；照旧理解会让门禁和 schema 对不上
  - ❌ 把「来龙去脉」定义成「按时间读一遍」：用户给过两种查法（按时间先后 / 按血缘上下层），只有后者能跨分支，前者相邻两条未必相关
  - ✅ 四词各给「不是什么」+ 用户场景例句；索引额外附 token 对比，回答用户早先「索引会不会浪费」的疑问

## 四词定案（`暂定`）

| 词 | 一句话 | 关键排除项 |
|---|---|---|
| **记录** | 一件事的完整留档，一个文件一条 | 不是索引里的一行；不是流水账段落 |
| **索引** | 指向记录的定位表，只放定位信息 | 不是摘要；不是目录；不是副本 |
| **事件** | 六要素在语境里补得全、已被记录的一个发生 | 不是任务；不等于工作项（事件 ⊂ 工作项）|
| **来龙去脉** | 一件事的因果链，靠血缘走通 | 不是时间顺序；不是全部历史；不是扫索引的结果 |
