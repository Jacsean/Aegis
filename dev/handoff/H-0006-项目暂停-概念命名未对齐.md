# H-0006 项目暂停：概念命名未对齐

- **时间**：2026-10-21
- **谁**：agent（会话 21 续）+ 用户
- **事件**：用户决定暂停项目推进，先处理「概念命名未对齐」这个从项目一开始就存在的隐患
- **为什么这样处理**：本轮讨论中连续三次鸡同鸭讲（位置 / 分支 / 树），根因不是理解偏差，而是**关键概念从未命名、从未固化**。这些概念不只 handoff 在用——阶段、制品、门禁从 v1.0.0 就在用，但从来没定过「不是什么」。若不暂停继续写 schema，所有改动都会建立在词义未定的沙地上
- **怎么处理的**：打 tag `v1.3.2-pause` 冻结现场；本记录 + 暂停标记 + `CONCEPTS.md` 骨架为新增文件，**暂停期间禁止改写任何现有规范**。回来后按依赖分五层梳理概念（元概念 → 骨架 → 文档记录 → 协作 → 交付），每层独立验收
- **试过什么**
  - ❌ 继续推进 handoff 本体设计：推演后放弃——「位置」一旦按新定义改，会连带模板、门禁、5 条记录，全建在未对齐的词上
  - ❌ 只把概念表当梳理期的临时工具：用户纠正——agent 交接、用户查阅都要用，须是长期制品（国军标先例：每份文档开头有概念定义 + 全文统一术语表）
  - ✅ 概念条目格式：**记叙文六要素为上限、按需取用**（用户定）+「不是什么」必填（agent 加，本次事故的直接教训）。三个词实测：地点 3 元素、分支 4 元素、意图校准 4 元素，均 150 字内
  - ✅ 分五层按依赖排序：上层词会出现在下层定义里，顺序倒了定义会引用未定词，原样重现鸡同鸭讲
- **下一步 / 等谁**：agent 写第一层「元概念」六词条（事 / 时间 / 地点 / 人物 / 起因 / 结果）→ 交用户验收 → 用户点头再进第二层。**未验收前任何规范文件不动**
