# H-0002 用一次性 HANDOFF.md 做交接

> ⚠️ **本条已废止（2026-10-21）**：一次性重写会冲掉历史，用户要的是可检索的开发事件档案。
> 现行做法见 H-0005。本文件保留不删，用于说明为什么改了。

- **时间**：2026-10-20
- **谁**：agent（会话 19）
- **事件**：在仓库根目录建 `HANDOFF.md`，作为「下次开工先读这份」的续接点
- **为什么这样处理**：用户下班前要求保存设计结果，当时判断「设计上下文只在对话里，git 里没有下一步该做什么」，于是写了一份
- **怎么处理的**：`HANDOFF.md` 六节：当前状态 / 已完成的两个设计 / 下一步待办 / 未进版清单 / 协作约定 / 停止位置
- **试过什么**
  - ✅ 当时有效：下次开工确实靠它接上了上下文，没有回头翻对话
  - ❌ 长期不可行：设计目标是「一次交接」，每次重写覆盖；用户需要的是「可检索以往做了什么、遇到什么问题、怎么解决」——这两个用途相反
- **下一步 / 等谁**：已被 H-0005 取代。`HANDOFF.md` 保留，但定位改为「当前任务的实时状态」，不再承担历史检索
- **上接**：无
- **下接**：H-0005（改为两层结构）
- **位置**：`HANDOFF.md`
