# DESIGN · eight-stage

## 1. 模块划分
- **场景决断**（.ai/09）：关键字字典 + 路由表 + 升格/降格规则
- **八阶段文档**（.ai/10~17）：阶段卡（必答/出口/门禁要点）+ 附录（九阶段原样移植）
- **机器层**：gate.sh（S 别名映射 + 包内模式）、state.sh（S 正则）、Makefile（gate-s1~s8）、sync.sh（skill 新名）
- **回溯层**：dev/legacy/（九阶段原件）+ PATH-MAP 追加行

## 2. 关键取舍（显式权衡）
- **别名映射 vs 重写门禁**：选别名（旧检查逻辑已实测 34 项，重写风险大、收益低）——门禁内部旧名属回溯层
- **附录带原文 vs 只留阶段卡**：选带原文（手法细节是使用中要用的，不能随 legacy 丢失）
- **skill 1:1 改名 vs 合并**：选改名（p3+p5 检查块在 gate 已合并，skill 层保持两个入口对应两个检查点）

## 3. 放弃的选项
- 重写全部门禁脚本：工作量大且丢已验证逻辑
- 场景决断做 S0 阶段：无出口制品，纯增门禁负担（U12 已裁）

## 4. 错误路径设计
- 场景决断判不出场景 → 问答细化（五元素）→ 仍不能 → agent 推断并声明不确定性（U12）
- S5 发现方案级破绽 → 回 S4；需求级 → 回 S2/S3；不视为失败（退回不是失败，是省钱）
- 门禁 FAIL → 停在当前阶段，按提示补制品；FORCE=1 需记录豁免
- 包内模式缺 dev/ → 跳过设计者维度检查并告警一次（不阻塞使用者任务）
- 落地后发现八阶段缺口 → 记入 dev/eight-stage-plan/ 未决清单，走修订留痕三动作
