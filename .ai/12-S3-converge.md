# S3 · 收敛（手法细则）


> 目的：把"想要什么"变成"用户签字确认过的需求"。
> **本阶段禁止写任何业务代码。**

---

## 输入

- 用户的需求描述（一句话也可以）
- `docs/INDEX.md`（了解已有资产，避免重复）

---

## 动作清单

### 1. 苏格拉底式提问（先问，不要先给方案）

按此顺序问，一次问 3-5 个，不要一次问完 20 个：

**第一轮 · 目标与边界**
- 这个项目/功能要解决谁的什么问题？
- 做到什么程度算成功？（可测的标准）
- **明确不做什么？**（非目标 —— 最常被跳过，最能防范围蔓延）

**第二轮 · 用户与场景**
- 谁会用它？在什么情况下用？
- 主流程走一遍是什么样？（一步步说）

**第三轮 · 约束**
- 有无技术限制（必须用某框架 / 必须离线 / 性能要求）？
- 有无时间或复杂度限制？
- 与现有系统的关系？

**第四轮 · 界面（前端类项目必问）**
- 有哪几个关键界面？
- 每个界面的核心元素是什么？
- 交互风格偏好（简洁工具型 / 丰富展示型 / 其他）？

> 若用户的回答含糊，**追问到具体**。含糊的 PRD 会导致 S4 反复返工。

### 2. 写 PRD

用 `.ai/99-reference/prd-schema.md` 的六节结构，写入 `docs/prd.md`。

### 3. 逐条核对（关键步骤）

写完后，**逐条念给用户确认**，不要只说"PRD 已生成，请查看"。

格式：
```
PRD 已写入 docs/prd.md，请逐条确认：

1. 目标：<一句话>
2. 非目标：<列出>
3. 关键界面：<列出>（决定 S4 要出几个 demo）
4. 验收标准：
   - <可测标准 1>
   - <可测标准 2>

以上是否正确？有需要调整的地方请指出。
```

### 4. 登记

- 在 `docs/INDEX.md` 登记 `prd.md`
- 更新 `STATE.md`

## 必备制品

| 制品 | 路径 | 要求 |
|---|---|---|
| 需求文档 | `docs/prd.md` | 六节齐全，**非目标非空**，验收标准可测 |
| 索引登记 | `docs/INDEX.md` | 含 prd.md 一行 |
| 状态更新 | `STATE.md` | 阶段 = S3，下一步指向 S4 |

---

## 出口门禁

- [ ] PRD 六节齐全：背景 / 目标 / 非目标 / 用户场景 / 验收标准 / 关键界面清单
- [ ] **「非目标」至少 1 条，且是真的"不做什么"**（不是"暂不做"的模糊话）
- [ ] 每条验收标准都可测（能回答"怎么验证它做到了"）
- [ ] 前端项目：「关键界面清单」非空，且每个界面写了核心元素
- [ ] 没有未决问题，或有明确标记为"挂起"的问题及原因
- [ ] `bash scripts/gate.sh S3` 输出 PASS
- [ ] **用户明确回复"确认"**

---

## 人工确认

✅ **强制签字**。agent **不得自行判定通过**。

判定标准：用户说出"确认""可以""没问题"等明确肯定词。
模糊回应（"嗯""看起来行"）不算确认，需再次询问。

签字记录写入 `STATE.md`：
```
- S3 PRD 确认：<日期> 用户确认 ✅  <用户原话摘录>
```

---

## 常见失误

| 失误 | 后果 | 纠正 |
|---|---|---|
| 跳过提问直接写 PRD | 需求跑偏，S4 全返工 | 必须逐轮提问 |
| 非目标写"暂不考虑其他功能" | 等于没写，无法防蔓延 | 必须写具体不做什么 |
| 验收标准写"体验良好" | 不可测，无法验收 | 改成"列表页 1 秒内加载完成" |
| PRD 生成后不逐条核对 | 用户没真读，问题延后暴露 | 必须逐条念给用户 |
| agent 自行判定"用户应该同意了" | 违反铁律一 | 必须等明确肯定词 |
| 前端不列关键界面 | S4 无法确定要出几个 demo | 必填 |
