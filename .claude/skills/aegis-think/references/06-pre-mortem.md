# 事前验尸

## 它逼你想什么

普通复盘是"失败了以后找原因"。事前验尸是**假设现在就已经失败了**，倒推原因。它绕开了"我觉得不会失败"的自我安慰。

## 怎么用

1. 设定场景：**"三个月后，这个任务被判定为失败。"**
2. 写下最可能的 3 个原因（要具体，不要写"需求没对齐"这种空话）
3. 每个原因问：**现在能做点什么把它排除？**
4. 排除不了的 → 那是一条需要向用户确认的假设

## 例子

> "贪吃蛇做完了，但被判定失败。"

三个最可能的原因：
1. 用户打开一看是命令行程序，根本不是他想的样子
2. 能玩但手机上完全没法操作
3. 功能齐全但没有一点"能看"的界面，用户觉得等于没做

→ 第 1 条现在就能排除：**问一句"要浏览器能玩的，还是源码就行"**
→ 第 2 条现在能排除：**顺手做成响应式**（成本很低）
→ 第 3 条：**先给一个极简但像样的样式**，不做裸 HTML

## 什么时候不该用

- 任务极小、失败成本几乎为零
- 用户明确说"先随便做个原型，别考虑那么多"
