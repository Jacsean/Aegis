# 二阶思维

## 它逼你想什么

每个决定都有"然后呢"。**一阶思维看到立刻的结果，二阶思维看到后果的后果。**

## 怎么用

对每个方案连问两次"然后呢"：

1. 这么做 → 会发生什么？（一阶）
2. 然后呢 → 那又会引起什么？（二阶）
3. 如果二阶结果和你要的相反，方案要改

## 例子

> 方案：把贪吃蛇做得功能齐全（计分、难度、音效、排行榜）。

- 一阶：用户会觉得"做得挺全"
- **二阶：但他要的可能是"看看你能不能干活"，功能越多，他越难快速判断做得好不好**

→ 结论反转：**对这次交付，做少而精比做全更有价值。**

再一个：
> 方案：为了让代码好看，拆成 HTML + CSS + JS 三个文件。

- 一阶：结构清晰、专业
- **二阶：用户双击打开时遇到跨域限制，直接玩不了**

→ 改成单文件内联。

## 什么时候不该用

- 决定的影响范围极小（改个文案）
