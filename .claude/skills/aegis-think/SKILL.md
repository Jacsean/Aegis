# 先想再做

## 这个 skill 解决的问题

接到任务的**第一反应**决定结果质量。常见的两种第一反应：

| 反应 | 结果 |
|---|---|
| 顺着字面立刻做 | 交出去的东西是"他要的",不是"他需要的" |
| 问一句"你是这个意思吗"就做 | 好一点,但仍在自己设的框里打转 |

**第三种反应**是资深的人会做的:停下来,换几个角度把这件事本身重想一遍,再问。

差别不在聪明,在**用不用工具**。这个 skill 提供那几把工具。

## 什么时候用

- 用户提出一个新要求、新任务
- 要求很短、很模糊、或能理解成好几种意思
- 用户说的和用户可能要的不完全是一回事
- 你觉得"这很简单,直接做就行" —— **这时候最该用**

**不该用**：用户已明确到无可歧义（"把第 12 行的 typo 改掉"）、或只是追问上一条的细节。

## 怎么用：先自问缺什么，再挑模型

**不要先挑模型**。先自问四句话，缺哪句就补哪个：

| 自问 | 如果答不上来 | 用什么模型 |
|---|---|---|
| 他说不出"为什么要这个",我补不上 | 缺**目的** | `01-first-principles` 第一性原理 / `04-5why` 连问五层 |
| 我说不出"做到哪算够" | 缺**范围** | `08-mece` 互斥穷尽 / `03-5w2h` |
| 我不知道有哪些限制(时间/平台/存量/预算) | 缺**约束** | `03-5w2h` |
| 我说不出"怎样算做好了" | 缺**判据** | `05-inversion` 逆向 / `06-pre-mortem` 事前验尸 |
| 我分不清这是简单问题还是复杂问题 | 缺**分类** | `07-cynefin` |
| 我不确定自己的理解偏在哪 | 缺**自检** | `10-ladder-of-inference` 推论阶梯 / `12-steel-man` 反方最强论证 |
| **我只会问"要不要加这个功能"** | **缺主张** | `13-kano` 需求分类 / `14-peak-end` 峰终定律 / `15-design-thinking` 设计思维 |

**一次只补 1-3 个缺口。** 补 4 个以上就会变成填表，反而没人认真看。

最后一行最容易被忽略：**如果你只会问"要不要 A、要不要 B"，说明你在做填空题，不是在思考。** 那时该用 13/14/15，先形成自己的判断。

## 输出：先给主张，再请确认

```
1. 我理解你要的是：<A>（依据：你那句"..."）
2. 我判断你真正需要的是：<X>
   依据：<用哪个模型看出来的>
   所以我打算这么做：<具体做法>
3. 还可能是 <B> / <C>；如果你更想要那个，我改
4. 请确认，或直接否掉第 2 条
```

**第 2 行是分水岭。** 没有主张 = 只是把决定权推回给用户，那不是深思熟虑，是填空题。

**什么时候给主张、什么时候只给选项**：

| 情况 | 给什么 |
|---|---|
| 有明显更优解 | **给主张**——"我建议这么做，理由是…" |
| 真两难（取决于用户偏好） | 给选项——"这两种各有代价，你选" |
| 分不清 | **给主张**。用户否掉一个主张，比从零做选择省力 |

如果用户的回答让你发现理解偏了，**先说"我原来理解成 X，现在改成 Y"，不要默默改**。

## 记录：把想过的留下来

用这个 skill 得出的判断，必须写进项目的 `NOTES.md`（格式见下），**否则下次会话又要重想一遍**。

```markdown
## <日期> <任务一句话>
- 用了：<模型名>
- 我理解你要的是：A
- 排除的：B（理由）、C（理由）
- 我猜你还需要：D、E
- 什么情况说明我理解错了：<一句>
- 状态：待确认 / 已确认 / 已被推翻
```

## 什么时候可以说"我信息不足"

补完 1-3 个缺口后，如果仍然无法确定，**允许弃权一次**——但必须同时满足四条：

1. **只说一次**：同一次任务里不能连续弃权。第二次必须自己拍。
2. **列具体缺口**：不能写"信息不足"，要写"我不知道 A / B / C 里的哪一个"，最多 3 条。
3. **给对比后果**：每条缺口说清"选这个会怎样、选那个会怎样"，让对方一句话就能选。
4. **给最小开工点**：说明"告诉我哪一条我就能开工"，而不是把整件事推回去。

格式：

```
我在这两点上确实不确定，任何选择都是猜：
1. <缺口一>：选 A 会…；选 B 会…
2. <缺口二>：选 C 会…；选 D 会…
任意告诉我一条，我就能开工。
```

**绝对不许这样写**：

| 错误写法 | 为什么不行 |
|---|---|
| 「信息不足，请补充需求」 | 把活推回去了，等于没干 |
| 「你能说得更具体点吗」 | 没说自己缺什么，对方不知道从哪补 |
| 「我先按 A 做，你看看」 | 这不是弃权，是偷偷猜，且浪费了一轮返工 |

**为什么需要这一节**：模型被训练成"总能给出答案"，因为训练时的评分偏好"直接给完整答案"而非"反问"。所以"说不知道"需要被显式允许，否则它一定会硬做一个版本。

## 三条纪律

1. **不许为了显得想过了而堆模型。** 用 1 个就够时不要用 3 个。
2. **不许把推测说成结论。** 拿不准就写"我猜"。
3. **不许沉默地改主意。** 理解变了要说出来。
