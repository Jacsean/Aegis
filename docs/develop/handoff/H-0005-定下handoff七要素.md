# H-0005 定下 handoff 记录的七要素

- **时间**：2026-10-21
- **谁**：agent（会话 21）+ 用户
- **事件**：定下开发事件记录的七要素格式，替代原先申请式的一次性交接文档
- **为什么这样处理**：用户提出「我心理没明确答案时，不找答案，找问题涉及的规则」——把「写几行算够」换成「用哪套成熟规则定要素」，于是引用 5W2H / 记叙文六要素 / 事故交接模板 / 复盘设计原则四类来源，定出七要素。〔推断〕这套要素能覆盖大多数任务；尚未在真实长项目上验证
- **怎么处理的**：新增 `.ai/99-reference/handoff-schema.md`（两层结构 + 七要素 + 三态标注 + 血缘链接 + 废止规则），配套 `templates/docs/HANDOFF-index.md` 与 `templates/docs/handoff/README.md`
- **试过什么**
  - ❌ 一次性重写的 `HANDOFF.md`：业界主流做法（存临时目录、不进仓库），但用户要的是「可检索的历史」，一次性重写会把历史冲掉
  - ❌ 纯流水账：grep 快，但单条太浅、跨条太散，查一件事要读中间夹着的不相干记录
  - ❌ 纯目录树：一件事可能横跨两个任务，目录只能放一个位置
  - ✅ 两层 + 血缘链接：索引一行（快扫）+ 记录一页（读懂）+ 上接下接（走上下游）
  - ✅ 七要素而非「5-8 行」：行数取决于内容，要素才决定完整性；且门禁可查
- **下一步 / 等谁**：〔未知〕用户看完实物样例后，是否认可这套格式；若不认可，要调整的是「要素清单」还是「两层结构」，需用户指出
