# H-0016 文档一致性补齐：索引漏登记与旧字段

- **时间**：2026-10-21
- **谁**：agent（用户授权「随你处置」，约束是「不影响执行结果」）
- **事件**：修掉门禁查不出的两类漏：INDEX 漏登 10 条记录、8 条记录仍用旧字段「位置」；并堵住「整目录登记」豁免造成的假 PASS
- **为什么这样处理**：用户指出「每遇到一个问题就建一个新文件，但新文件与原文档系统没有可追溯关联，导致问题越切越细、原文档没改全、有遗漏」。实证：P6 门禁当场报 PASS（`docs/ 下全部文档已登记 INDEX`），而 INDEX 实际只登记到 H-0005，H-0006~H-0015 十条全漏——因为 `gate.sh` 认可「整目录登记」，`develop/handoff/` 一行就把整个目录放行了。**闸看着是绿的，漏是隐形的**，所以先补数据、再把豁免堵掉
- **怎么处理的**：
  1. `docs/INDEX.md`：补登 H-0006~H-0015 十条
  2. 旧字段按新定义改写：H-0001 / H-0002 / H-0003 / H-0004 / H-0005 的「位置」→「地点」（commit、tag 归「怎么处理的」）；H-0007 / H-0009 / H-0014 补「地点」
  3. `scripts/gate.sh`：INDEX 完整性检查对 `docs/develop/handoff/*` 取消目录豁免，必须逐条按文件名登记
  4. `docs/develop/CONCEPTS.md`「地点」词条：把「`handoff-schema.md` 现在写…」改为「曾写…，H-0015 已改」，去掉已过时的事实陈述
  5. `STATE.md`：划掉已完成的 S5/S6/S7，删除「元概念作用域未定」等已结案限制，补上 Windows 软链会被展开的限制
- **试过什么**
  - ❌ 直接信门禁 PASS：跑过才知道 P6 的 INDEX 检查对 handoff 目录是豁免的 → 改为逐文件检查
  - ❌ 只补 INDEX、不修 `gate.sh`：下次新建记录还会漏 → 同时堵闸
  - ❌ 只改 schema、不回头改旧记录（H-0015 当时的做法）：8 条记录仍用「位置」→ 本轮补齐
  - ✅ 体检一次性列出「未登记 / 缺要素 / 作废词残留」三类：比人眼看快，且每条都能复核
- **下一步 / 等谁**：④协作、⑤交付两域梳理时按新闸走——新建任何记录当场挂 INDEX，否则 P6 直接 FAIL。用户确认后可合并回 main 并升版本
