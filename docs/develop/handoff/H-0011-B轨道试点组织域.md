## 逐条说明

### S1（Q1）工作项缺驻留位置

现定义只说工作项"在三级结构上被承载、传递"、有可追踪状态，**没说状态记在哪**。会话结束，工作项就没了落点。

**建议**：工作项不单独持久化；跨会话未闭合的工作项，必须在 `STATE.md` 的「进行中」列出，并在该任务 handoff 记录的「下一步 / 等谁」点名。
**代价**：小（一条规则 + STATE 模板一处）。

### S2（Q2）共识缺生效条件

定义只说"双方此后按同一理解行事"，**没说"双方"是谁、谁确认才算数**。两个 agent 各自提炼的共识冲突时无解。

**建议**：共识必须注明确认者；未确认的标 `暂定`；冲突时以用户确认为准，agent 之间的共识不得覆盖用户确认过的条目。
**代价**：小（条目加一行 + 状态三态已有）。

### S3（Q3）记录粒度与工作项粒度不匹配

handoff 是**任务级一条记录**，工作项是任务内更细的单元。工作项跨会话变更时，无处记录。

**建议**：保持任务级一条记录不拆；但"跨会话未闭合的工作项"必须在该记录的「下一步 / 等谁」写清，否则不许合并进 main。
**代价**：小（写入 P6 规范 + 门禁提示）。**这是一项设计选择**：也可以选择"为工作项单独立记录"，代价大得多（记录数量爆炸）。

### S4（Q4）缺「修订」规则，只有「作废」

现有"只增不删、过期划掉指向新词"针对的是**作废**。但本轮真实发生的是**修订**：用户先说"六要素必须齐"，后改为"按需取用"——词条没作废，定义变了。这种情况现在无规则。

**建议**：词条状态扩为四态——`已定` / `暂定` / `已修订`（保留旧定义 + 修订日期）/ `已作废`（划掉指向新词）。
**代价**：中（每条加修订记录 + 门禁查"已修订是否有日期"）。

### S5（Q5）启动协议未接概念表 —— 最严重

`AGENTS.md` 会话启动协议是：①`AGENTS.md` ②`STATE.md` ③`00-core.md` ④`90-preferences.md` ⑤按阶段加载 ⑥声明。**没有一步读 `CONCEPTS.md`。**

后果：**概念表做得再好，新 agent 启动时也不会读到它——整套机制空转。** 这是 B 轨道最大的收获，此前所有讨论都没发现。

**建议**：协议插入第 3.5 步"读 `CONCEPTS.md` 目录页（约 200 tokens）"；P0 门禁加"`CONCEPTS.md` 存在且目录非空"。
**代价**：小改动，但 `.ai/`、`AGENTS.md`、`scripts/` 属暂停期禁区 → 只能记待办，暂停结束后第一件事就做。
