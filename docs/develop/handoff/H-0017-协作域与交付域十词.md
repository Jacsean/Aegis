# H-0017 ④协作域 + ⑤交付域十词（暂定）

- **时间**：2026-10-21
- **谁**：agent 执行，用户「下一步」授权
- **事件**：写出 ④协作域（讨论/校准/签字/追问/五元素）与 ⑤交付域（交付/验收/缺陷/复发/预防）共 10 个词，状态 `暂定`
- **为什么这样处理**：这两域直接决定「你和 agent 怎么对话、什么时候算谈完、什么算做完了」，是十六词之后唯一还空着的两块。五域查完，概念体系才闭合
- **怎么处理的**：每词给「上位+区别特征 / 判据 / 不是什么 / 场景验」；**场景全部取自本轮真实发生的事**，不取想象（这是分工原则要求的）
- **试过什么**
  - ❌ 按字典义写「讨论 = 交换意见」：等于没定义。改为「就一个待定判断点交换判断」，判据是「谈完能指出分歧在哪、定了哪个」
  - ❌ 把「签字」写成「用户同意」：太软。改为「记在 STATE.md 并附原话」，沉默与「看着还行」明确不算
  - ❌ 把「预防」写成「补测试」：那只覆盖一例。改为「加的机制能拦住它」，拦不住的只能叫提醒
  - ✅ 每词拿本轮真事验：「探明」那次讨论失败、你说「对」算签字、「下一步」不算、「分支」当时该追问却没问、本次真机验收 = 验收的样板

## 十词一览

| 域 | 词 | 一句话 | 关键排除 |
|---|---|---|---|
| ④ | 讨论 | 就一个待定判断点交换判断 | 不是汇报、不是辩论、不是聊天 |
| ④ | 校准 | P0.5 两轮，把意图对齐到能写 PRD | 不是需求评审（对象不同）|
| ④ | 签字 | 阶段出口的明确确认 + 原话 | **不是「没反对」**；不是 agent 自称完成 |
| ④ | 追问 | 紧接上一问、把含糊处逼具体 | 不是换说法重问；不是另起话题 |
| ④ | 五元素 | 提问按需带的五个部件 | **不是五个都得写**；不是话术 |
| ⑤ | 交付 | 交给使用者并让其自己能用 | 不是「代码能跑」；不是 P6 归档 |
| ⑤ | 验收 | 使用者按自己标准判断能不能用 | **不是 agent 自测**；不是「跑通了」 |
| ⑤ | 缺陷 | 与应有行为不符且能复现 | 不是「不好用」（那是建议）；不是没做 |
| ⑤ | 复发 | 同一缺陷修好后又出现 | 不是症状相似的新缺陷 |
| ⑤ | 预防 | 加的机制能拦住它 | **不是「下次注意」**；不是补一个测试 |

## 本轮的真实验证

「签字」与「验收」两词，今天各有一个现成例子：

- 你说「对」→ 签字生效，词条转 `已定`
- 你说「下一步」→ 只是让我继续，不是签字（当时我没区分，细则现在写清了）
- Reasonix 不给前情答对两词 → 这是「验收」的样板：**换个人也能用，才叫验收**

- **下一步 / 等谁**：用户看十词是否撑得住；撑得住转 `已定`，五域闭合。之后进 P6 归档：重写 STATE、更新 INDEX、打 tag
