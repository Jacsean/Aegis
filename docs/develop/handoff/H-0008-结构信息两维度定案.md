# H-0008 结构/信息两维度定案 + 协作加一条「复述原话」

- **时间**：2026-10-21
- **谁**：用户 + agent
- **事件**：定下「结构（维度一）」与「信息（维度二）」两维度，三级结构 = 项目 / 任务 / 会话，工作项单列为信息维度；并新增一条协作规则：agent 下结论前必须复述得出该结论的用户原话
- **为什么这样处理**：用户连续两轮指出 agent「完全糊涂了」。查证属实——`CONCEPTS.md` 提交版写的是「项目 → 任务 → 工作项」，而 agent 口头说的是「项目 / 任务 / 会话」，文件与口头互相矛盾，且 agent 还回头重问已经定过的问题。根因是用户原话本身存在前后两版（第一版列「项目、任务、事/东西」，第二版补「会话是多轮构成任务的媒介」），agent 把第一版当结论写进文件后，没随第二版回改
- **怎么处理的**：
  1. `docs/develop/CONCEPTS.md` 重写：`〇 · 两个维度（不是四层）` 一节明确「结构 ≠ 信息」，结构三层为项目/任务/会话，工作项移出结构图、单列「维度二 · 信息」
  2. 任务、会话、工作项三个词条的「不是什么」全部按新结构重写（任务不再写「会话不进术语表」；工作项明确「不是结构层」）
  3. 补例句：会话两条、工作项三条、项目任务各一到两条
  4. 新增协作规则见下
- **试过什么**
  - ❌ 第一版：三级 = 项目/任务/工作项，并写「会话是宿主概念，Aegis 管不着」——用户指出这是回避，会话存在于每个任务里且是结构的一部分
  - ❌ 第二版：问「会话算层级还是算通道」——概念错误：把「手段」当成可以和「包含关系」并列讨论的东西
  - ❌ 第三版：问「三层还是四层」——用户指出这是伪问题：结构与信息是两个维度，不是层数之争
  - ✅ 第四版：两维度并列图示 + 工作项移出结构，用户确认
- **新增协作规则（用户 2026-10-21 提出）**：**agent 根据用户语言总结结论时，必须把得出该结论的原话复述出来**，用户确认时同时检查自己的原话是否有语病或口误导致结论偏差。原因：用户口述会含错别字与口误，agent 不能只甄别不反馈，也不能默默修正——复述原话让两边都能查
- **下一步 / 等谁**：该协作规则应写入 `.ai/90-preferences.md`（暂停期禁止改 `.ai/`，已挂 STATE 待办）。概念梳理继续：元概念 → 地点 → 分支 → 树
- **上接**：H-0007（概念定义应为基石环节）
- **下接**：暂无
