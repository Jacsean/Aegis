# H-0009 用「共识」替代「元概念」+ 五层改五域

- **时间**：2026-10-21
- **谁**：用户 + agent
- **事件**：把信息维度二的第二个词定为「共识」（agent 从工作项中提炼出的一致理解），元概念从定义区移出、单列「待重新梳理」；五层梳理计划改为五域（域 = 定义顺序，不是内容分类）
- **为什么这样处理**：元概念从提出起就被双方按各自推测使用——用户原话「我在刚开始讨论元概念时，就没理解元概念讨论的意义，只是从 aegis 未来作用的角度，自作主张的认为它解决会话中涉及概念及需要统一认知问题」。定义域不清的词继续当定义用，只会把歧义焊进后续规范。故先用「共识」固化**实际达成的那部分理解**，元概念本身退回去重新梳理起因/范围/约束/作用对象
- **怎么处理的**：
  1. `docs/develop/CONCEPTS.md`：维度二信息 = 工作项 / 共识；共识「来源：工作项」，**不预设与元概念的关系**
  2. 新增「待重新梳理：元概念」一节，列四问（起因/范围/约束/作用对象），明确「当前不给定义」
  3. 「五层梳理计划」改为「五域」：组织 / 骨架 / 文档记录 / 协作 / 交付，并写明**域是排序工具，不是分类图**；域名字用范围名而非内容名（否则每层填充物与层名重叠）
  4. 删掉「元概念 关联：项目/任务/会话」那条边
  5. 新增「本表是什么 / 不是什么」对照表，防止用途歧义
- **试过什么**
  - ❌ 元概念 = 五层里的第一层：用户指出它不是层——每层的词条都是它，把它当层等于放错位置
  - ❌ 元概念 = 工作项的一个类型（改名「概念型工作项」）：凭空多一个词，违反精简必要；且推不出「要求/缺陷/决定也该有固化条目」的结论
  - ❌ 工作项 → 共识 → 元概念 三节点链：agent 自作主张给共识安了「中间身份」。用户纠正：共识是 agent 从工作项中**获得的东西**，不是链条中转站
  - ❌ 元概念 关联 项目/任务/会话：边不携带信息（任何词都在项目里被用），且层级错配（结构层 vs 词条）。用户质疑后删除
  - ✅ 工作项 →（提炼）→ 共识，元概念暂离场待重梳：用实际达成的共识替代推测，不留歧义
- **下一步 / 等谁**：元概念的四问需与用户逐项讨论（起因 → 范围 → 约束 → 作用对象），结论出来后再定它是否进本表、怎么定义。在此之前，任何文档提到元概念都必须标注「作用域待定」
- **上接**：H-0008（结构/信息两维度定案）
- **下接**：暂无
- **发生场景**：用户连续追问「元概念的关联描述是否合理」「五层里元概念是不是被狭隘了」「元概念是否该与三层结构直接关联」，指出 agent 反复给一个未定义词安排位置
- **地点**：本机，无外部场所（会话内讨论）；结论落 `docs/develop/CONCEPTS.md` 组织域
