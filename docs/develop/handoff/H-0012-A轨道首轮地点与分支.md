# H-0012 A 轨道首轮：「地点」「分支」查出两处定义错

- **时间**：2026-10-21
- **谁**：agent 执行，用户授权「继续」
- **事件**：按 H-0010 的 A 轨道查「地点」「分支」两词。两词都判不合格，已在 `CONCEPTS.md` 给出新定义（标 `暂定`）
- **为什么这样处理**：验收场景全部取自用户原话，不取 agent 想象——这是用户 2026-10-21 定的分工原则（`HANDOFF.md` 第七节）：用户给需求，agent 设计并用用户的要求做验证场景
- **怎么处理的**：逐词走「取证 → 列现有理解 → 用用户场景试填 → 判定 → 给出新定义」五步；原文全部贴出处
- **试过什么**
  - ❌ 先按 schema 现状认定「位置 = 文件路径 + commit」是对的：试填用户第二类场景（客户现场改需求）时填不出来，判不合格
  - ❌ 保留「树」作为记录结构的说法：用户定义里「树」是整张图、「分支」是一条枝，两词混用正是当初鸡同鸭讲的起点
  - ✅ 按「查的时候靠什么定位」定地点的粒度：代码查行号、需求查场所、文档查章节，三类都能填
  - ✅ 上接改为可写多个：否则 H-0009 这类「同时接两处」的记录必然断线
