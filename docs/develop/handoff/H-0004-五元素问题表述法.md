# H-0004 落地五元素问题表述法

- **时间**：2026-10-20
- **谁**：agent（会话 20）+ 用户
- **事件**：重写 checklist 的提问结构，从「判断依据 + 选项」升级为五元素
- **为什么这样处理**：用户原话是「你的问题缺乏必要的上下文……我的回答就可能和你的问题覆盖范围有差异」。诊断结论：原来的「判断依据」写的是 agent 怎么想的，用户想知道的是这话从哪来，两者不是一回事
- **怎么处理的**：改 `.ai/015-P05-align.md` 规则三与 R1/R2/R3 三套模板；改 `checklist-schema.md` 第三节；`gate.sh P05` 加三条检查；三份样例全部补齐
- **试过什么**
  - ❌ 只加「从哪来」一个字段：不足以解决「不知道凭什么选」
  - ❌ 五元素强制全有：用户明确否掉——「不强制要求 5 元素同时具备，应该根据问题内容，尽可能多的具备」
  - ✅ 按需取用 + 判断标准改为「用户判断错的代价」：用户接受，落地为 v1.2.0
- **下一步 / 等谁**：已完成。实测中是否够用，待真实任务检验
