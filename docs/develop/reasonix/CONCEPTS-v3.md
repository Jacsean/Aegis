## 外接（External capability）

**上位概念 + 区别特征**：不属于 Aegis、但被 Aegis 按统一规则引入并使用的外部能力。

### What · 是什么

外部能力本身（通常是第三方 skill），Aegis 不拥有、不改造，只决定三件事：**接不接、怎么验收、怎么记**。

与"自有"的分界：

| | 自有 | 外接 |
|---|---|---|
| 例子 | `aegis-think` 的 15 个思维模型、`NOTES.md` 记录、门禁检查 | 本地知识库 skill、Blender/SolidWorks 建模 skill |
| 谁写的 | Aegis | 别人 |
| 能改吗 | 能，随版本迭代 | 不能，也不能要求它改 |
| 拔掉会怎样 | Aegis 功能缺失 | Aegis 只是少了一种可调用的能力，框架本身完好 |

### Why · 为什么需要

**没有它会怎样**：Aegis 永远不可能自建所有专业能力（3D 建模、本地知识库、视频剪辑、音频处理……）。没有引入机制，它就只能停在"思维模型 + 流程"这一层，一旦任务需要专业能力就断掉。

**为什么不能"直接拿来用"**：直接用的三个后果——
1. 不知道它适不适合当前任务（用了不合适的工具，比不用更糟）
2. 不知道产出合不合格（跑完了，但结果对不对没人验）
3. 下次不知道用过什么（换 agent 或过三个月，等于没做过）

**外接补的就是这三件事**，不补第四条（它内部怎么实现，Aegis 管不了也不该管）。

### Who · 谁用

| 角色 | 用它做什么 |
|---|---|
| **agent** | 判断"这次要不要接"、调用前定验收标准、调用后验收并记账 |
| **使用者（你）** | 从记录里看"这个项目用过哪些外部能力、哪些失败了" |
| **第三方 skill 的作者** | **不用它**。他们不需要遵守 Aegis 任何规范——Aegis 管不了别人怎么写 |

> 这一条必须写明：**外接不是技术接口标准，是引入流程规范。** 混淆这两者会做出一个"没人遵守的标准"。

### When · 何时生、何时灭

| 时点 | 判断 |
|---|---|
| **生**（决定引入） | `aegis-think` 自问"我缺什么"，发现缺的是**能力**（不是信息），且自有能力补不上 |
| **不生**（不引入） | ① Aegis 自己能做 ② 判断不值得（成本 > 收益）③ 只需要问用户就能解决 |
| **灭**（本次结束） | 一次任务结束后关系不"消灭"，但**记录保留**；能力清单可复用 |

### Where · 在哪

| 项 | 位置 |
|---|---|
| 调用记录 | `NOTES.md` 的 `用了：` 行（最小版，现在就可用） |
| 产出物 | 每次调用前由 agent 指定并写进记录（不许"跑完再看看放哪"） |
| 能力清单 | 暂不建。等真接了 2 个以上再建，否则是一张空表 |

### How · 怎么用（三头管控）

```
① 调用前（用 aegis-think 的模型想）
   - 这任务真需要它吗？还是我自己能做？
   - 产出放项目哪里？
   - 怎么算合格？（先定标准，事后不许改）
② 调用中
   - Aegis 不干预。它是外部能力，内部怎么跑不管
③ 调用后
   - 按 ① 定的标准验收
   - 记入 NOTES.md：用了哪个、产出在哪、留下什么、卡在哪
   - 失败必须记"卡在哪"——这是判断"值不值得继续用"的唯一依据
```

### How much · 多少算合理

**一次任务引入的外接 ≤ 2 个。**

依据：技能同时激活越多，遵循率按乘法下降——4 个各 90% → 同时成立只剩 66%；6 个 → 53%。外接多了不是"能力更强"，是"每个都不牢"。

**超过 2 个说明任务太大，该拆任务，而不是硬接。**

### 不是什么

- ❌ **不是 Aegis 的功能扩展**——接上不会让 Aegis "多出"这个能力，拔掉就没有，Aegis 本身不变
- ❌ **不是插件市场**——Aegis 不做分发、不做安装
- ❌ **不是接口标准**——管不了第三方 skill 怎么写，只定自己这侧的流程
- ❌ **不是自建的替代品**——**能用自有就优先自有**，因为自有能力和记录/门禁天然一体，外接要额外做三头管控

### 例句

1. 「这次要给贪吃蛇加音效，接『音频生成 skill』」——**外接**，需要调用前定"什么样的音效算合格"。
2. 「用户问『为什么用 Canvas 不用 DOM』」——**不是外接**，这是 Aegis 自有能力（记录里有）能回答的。
3. 「项目要沉淀知识库，接『本地知识库 skill』」——**外接**，且 `NOTES.md` 不废弃，它降级成知识库的索引层。

### 与 4 个问题、2 个维度的对应

| | 外接机制怎么覆盖 |
|---|---|
| 问题 1 思考模式 | 调用前用思维模型判断"该不该用它"，而不是见到工具就用 |
| 问题 2 凭空捏造 | 外部产出必须标来源（它生成的？还是查到的？） |
| 问题 3 概念对齐 | 外部产出的术语要并入项目概念表，不许自造一套 |
| 问题 4 跨接无损 | 调用记录进 `NOTES.md`，换 agent 能接上 |
| 维度一 思维模型 | 决定"接不接、怎么验收" |
| 维度二 工程方法 | 实际的验收动作、记录格式 |
