## 四、装 Aegis 的执行步骤

```bash
# 1. 建一个空目录当项目
mkdir -p ~/projects/snake-with-aegis

# 2. 装上最小闭环
cd /d/example/projects/Aegis
bash scripts/install-v3.sh ~/projects/snake-with-aegis

# 3. 在该目录打开 Reasonix 新会话
# 4. 把"需求原文"一字不改地发出去
```

**不装的那组**：同样的空目录、同样的需求原文，只是不跑安装脚本。

## 七、token 怎么记

Reasonix 的用量记录在 `~/.reasonix/usage.jsonl`。

```bash
# 跑完后，取该会话的用量
tail -20 ~/.reasonix/usage.jsonl | grep <会话id>
```

若拿不到精确值，用粗略口径：**会话总输入 + 总输出**，并注明口径。

## 八、怎么判读

| 情况 | 结论 |
|---|---|
| 装的问得更多、多做的东西更贴合、token 差不多 | ✅ **维度一有效**，继续加深 |
| 装的问得更多但 token 明显更高 | ⚠️ 有效但太贵，要压缩 |
| 两组几乎一样 | ❌ **没测出差异**：要么任务太简单（换更模糊的任务），要么 skill 没被触发（查触发） |
| 装的更差 | ❌ 检查是不是问太多把用户烦到了，或问了没用的问题 |

**两次结果差异大**（同一组跑两次结论不同）→ 说明任务随机性太大，要换成更稳的任务，或增加运行次数。

## 九、已知局限（提前说明，免得误判）

1. **只跑一次，结论置信度有限**。业界做法是多次运行取中位数。资源不够时，至少要重复 2 次看是否稳定。
2. **贪吃蛇是"清晰问题"**，对维度一的考验有限。如果两组差异不明显，换一个更模糊的任务再测（比如"做个能记录每天心情的东西"）。
3. **这次只装了维度一 + 记录机制**，没装八阶段流程和 hook 强制。所以测的是"最小闭环"的价值，不是"Aegis 全部"的价值。
