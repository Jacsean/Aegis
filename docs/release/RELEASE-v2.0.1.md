# RELEASE · v2.0.1（步 4 验收泄漏修复）

> 状态：定稿 · v2.0.1

## 一、交付了什么

v2.0.0 的三处使用体验问题在本版修掉：

1. **旧版流程设计在使用路径上不再出现**：`.ai/00-core.md` 的铁律/三轴模型/制品总表/流转图、`.ai/11~17` 的阶段卡（含附录手法细节）、`.skills/`、`README.md`、`Makefile`、脚本用法注释，全部按语义改写为 S 体系编号
2. **失败定义变成可执行判据**：`scripts/check-no-legacy.sh` 扫描使用者维度，命中旧编号/旧文件名/旧流转图即退出码 1，出包前可重复执行
3. **交付包里不再刷门禁噪音**：`gate.sh` 检测到无 `dev/`（= 交付包）只跑框架自检（规范齐全 / 无 dev/ / 旧设计不可见 / 派生物一致），不再对骨架跑项目级 S1~S8

## 二、怎么用

- 出包前自检：`bash scripts/check-no-legacy.sh`（应输出 PASS）
- 交付包内自检：`bash scripts/gate.sh`（只跑框架自检，应 PASS）
- 按启动协议走流程：读 `AGENTS.md` → 启动协议 → 场景决断（`.ai/09`）→ 按 `STATE.md` 阶段加载 `.ai/1X-Sn-*.md`；门禁 `make gate-s1`…`gate-s8`
- 旧设计回溯：只走 git 历史（`dev/legacy/` 仅设计者维度，交付包内不含）

## 三、验证证据

```
$ bash scripts/check-no-legacy.sh
  ! 检测到 dev/（设计者维度）——若是交付包，说明剔除失败
PASS — 使用者维度 0 处旧流程残留（旧设计使用中不可见）

$ for p in S1..S8; bash scripts/gate.sh $p
S1 ✓9 ✗0 / S2 ✓28 ✗0 / S3 ✓8 ✗1(内容缺:S3签字) / S4 ✓5 ✗0 / S5 ✓1 ✗3(内容缺:REVIEW 文件)
S6 ✓4 ✗0 / S7 ✓15 ✗1(tag 待打) / S8 ✓10 ✗0
```

说明：S3/S5/S7 的缺项均为**内容缺失**（本分支没有设计评审与代码 review 留档、tag 尚未打），不是脚本缺陷——回归目的是确认门禁逻辑未被本次改动破坏。

包内复验（解包后在新目录）：

```
$ bash scripts/gate.sh
PASS — 交付包自检通过（包内不跑项目级 S1~S8 门禁：这是骨架，不是在用项目）
```

## 四、已知限制

- `CHANGELOG.md` 历史条目保留旧编号（「历史只增不改」，判据中已豁免）
- `docs/prd.md`、`docs/release/`、`docs/align/` 允许出现旧编号——它们要说清"从什么切到什么"，属变更说明而非使用引导
- 场景字典仍只有 4 类初始场景；领域扩展留同行检索点
- `.skills` 的 S5 拆成 `aegis-s5-falsify`（查设计）/ `aegis-s5-recheck`（查代码）两个入口，阶段是同一个

## 五、适用场景

所有使用 Aegis 的项目；本版是 v2.0.0 的修正版，建议直接使用 v2.0.1。旧项目回溯用 tag v2.0.0 / v1.6.1 及更早。
