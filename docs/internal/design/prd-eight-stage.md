# PRD · eight-stage（范围声明 + 失败定义）

> 状态：定稿 · 2026-10-21 · 对齐留档见 docs/rfc/ALIGN-eight-stage

## 背景
九阶段（含 P0.5）经结构审计被判分类错误（H-0021/H-0022），八阶段为讨论定稿；本任务将其落地。

## 用户
使用者 = 用 Aegis 开发项目的用户与其 agent；设计者 = 维护 Aegis 本身的人。

## 范围声明
把 Aegis 的流程骨架从九阶段（P0/P0.5/P1~P7）切换为八阶段（S1~S8 + 场景决断）：
阶段文档、门禁别名、skill、STATE/state.sh、Makefile、启动协议、INDEX/PATH-MAP 全部同步；
九阶段文件移 dev/legacy/ 仅回溯可读。

## 失败定义
新交付包内，agent 按启动协议走任何场景，能碰到九阶段设计 = 失败（步 4 真机验收判定）。

## 功能
场景决断模块；S1 立题与项目前提清单；S3 收敛（PRD 新六节）；S5 可重复两检查点；
S7 概念固化挂点随迁；包内门禁模式。

## 非目标
- 不做领域场景字典扩展（留同行检索扩展点）
- 不重写九阶段已验证的手法细节（原样移植）
- 不动两维度分离与 PATH-MAP 机制（仅追加 legacy 路径行）

## 验收标准
- 全部 S1~S8 门禁在仓库侧 PASS；交付包内九阶段 0 可见
- 新 agent 按启动协议只会读到 S 阶段文档与场景决断

## 风险
- 门禁内部仍以旧检查块名运行（P0~P7），已用 S 别名映射——若将来直接读 gate 源码会看到旧名（回溯层，不算使用者可见）
- 附录中保留了九阶段原文（标注「自九阶段迁移」），属移植出处说明，非使用指令

## 成功判据
见「验收标准」。
