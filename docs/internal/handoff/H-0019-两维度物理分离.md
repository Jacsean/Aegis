# H-0019 产物按设计者/使用者两维度物理分离

- **时间**：2026-10-21
- **谁**：用户提需求与裁决，agent 设计与执行
- **事件**：用户问「SKILL.md 面向谁」并要求产物按设计者/使用者两维度分离，交付只含使用者维度。定案：物理分离；概念表搬家
- **为什么这样处理**：用户原话「没有硬性要求物理还是逻辑分离；不过交付时容易缺漏、搞混交付物时，建议物理分离」——交付边界靠目录边界保障，比靠清单记忆可靠
- **怎么处理的**：
  1. 搬家：`docs/develop/CONCEPTS.md` → `docs/CONCEPTS.md`（使用者方）；`docs/develop/{HANDOFF.md,handoff/}` → `dev/`；`archive/` → `dev/archive/`。设计者维度全收进 `dev/` 一个目录
  2. 路径更新：AGENTS.md 启动协议与制品表、`.ai/00-core.md`、`07-P6-archive.md`、`handoff-schema.md`、gate.sh（`$ROOT/dev/handoff`）、sync.sh、INDEX、templates、examples、HANDOFF.md
  3. 新增 `scripts/deliver.sh <版本>`：克隆（保 git 历史+tag）→ 剔除 `dev/` → 自检使用者维度完整性（5 个关键文件 + 派生物一致）→ 打包
  4. INDEX 顶部新增「两个维度」说明；重叠文件一律归使用者方（如概念表、`.ai/`、gate.sh）
- **试过什么**

  - ❌ 概念表留在 dev/ 用清单特批：会长期存在「设计者目录里的文件是给使用者的」别扭，用户定「物理分离则搬家」
  - ⚠️ 已知限制：交付包内 `.git` 历史对象仍含 dev/ 文件（回退点功能保留）；工作树不出现
