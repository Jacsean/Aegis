# H-0020 概念定义环节定案：铁律七 + 三挂点（H-0007 设计落地）

- **时间**：2026-10-21
- **谁**：agent 设计，用户「开始」授权（H-0007 用户点名要记住）
- **事件**：设计并落地「概念固化」环节——不新增阶段，作为三个挂点的固定动作；强制力分三层
- **为什么这样处理**：用户原话「概念的出现不是在项目一开始就全部涌现」——所以固化必须是常设动作；又按精简必要原则，不为它新开一个阶段（多一个阶段就多一道门禁和一套制品），挂在现有阶段上最省
- **怎么处理的**：
  1. **铁律七「概念先定义后使用」**（`.ai/00-core.md`）：反复使用的词，禁止未定义就当已共识使用；写明三挂点动作表。顺带把全仓「六条铁律」口径统一为「七条」（清掉 STATE 待办里的口径不一）
  2. **挂点一 · P0.5 校准**（`.ai/015-P05-align.md`）：校准开始必须产出「新词候选清单」，逐个用五元素问用户，当场起草词条标 `暂定`；没有写「无」
  3. **挂点二 · 任务中**：新词先命名再讨论，达成一致理解即写入概念表（用户在概念梳理轮已确立的规则，铁律里引用）
  4. **挂点三 · P6 归档**（`.ai/07-P6-archive.md` + `handoff-schema.md`）：handoff 记录必填第 8 项「**新词**」（无写「无」）
  5. **门禁**（`scripts/gate.sh`）：P6 机械检查最新记录的新词行，缺失告警（不阻塞——告警级强制，靠人复核）
  6. 模板 `templates/docs/handoff/README.md` 同步；`.skills/` 由 sync.sh 重新生成
- **试过什么**
  - ❌ 新增「概念固化阶段」（P8）：违精简原则，阶段越多跳步越多，否
  - ❌ 门禁硬阻塞（缺新词行就 FAIL）：机械检查判不出「该有新词而没有」，误报会教人糊弄格子，降为告警级
  - ❌ 把「概念固化」收进概念表：它是我方流程动作名，不是多义风险词，收录判据（不同语境理解不一致）不满足，不收
  - ✅ 机制自验：gate.sh 立即对 H-0019 报「缺新词行」告警——上轮记录本就没写新词行，检查真实生效；本条记录已按新规写新词行
- **新词**：无（本任务未产生需用户定义的新词；「概念固化」经判据判定不收录，见上）
- **下一步 / 等谁**：用户按验收单判形态与强制力是否可用

- **下接**：暂无
